## P0 最高优先级

### P0-1 继续打磨 v24 首屏高级感

- 任务说明：在不使用视频、不使用动画、不删内容的前提下，继续提升首屏静态 Hero 的高级感、品牌记忆点和咨询公司气质。
- 当前状态：v24 已恢复完整内容，并把首屏改为左文案 + 右香港图。桌面和手机预览可用。
- 为什么重要：首屏决定用户第一印象，用户明确要求不是廉价中介，也不是短模板。
- 建议下一步：基于当前 v24 小范围调整字体比例、图片裁切、导航高度、CTA 层级和香槟金细节；每次只改一个范围，保留可回滚版本。

### P0-2 移动端首页全链路复查

- 任务说明：重点检查 390px 手机宽度下导航、首屏、数据区、服务区、案例、导师、表单和二维码。
- 当前状态：v24 已验证 390px 无横向滚动，数据卡片无溢出。
- 为什么重要：家长和学生很可能通过手机打开官网，手机端第一印象直接影响咨询转化。
- 建议下一步：用 Safari 或 Playwright 逐屏截图，标记文字过密、图片过高、按钮间距、表单填写体验问题。

### P0-3 统一邮箱与联系方式

- 任务说明：确认最终对外邮箱到底使用 `info@rainedu.hk` 还是 `info@rainedu.com`，并统一全站。
- 当前状态：当前项目代码使用 `info@rainedu.hk`；用户提到邮箱优先可使用 `info@rainedu.com` 或项目中已确认邮箱。
- 为什么重要：联系方式不统一会影响品牌可信度和真实咨询转化。
- 建议下一步：等待用户确认最终邮箱；确认后全站替换，并检查结构化数据、页脚、隐私政策、表单说明。

### P0-4 GitHub 大文件策略

- 任务说明：处理 v21 和 v22 历史部署包超过 GitHub 100MB 普通 blob 限制的问题。
- 当前状态：本地存在 105MB、105MB、144MB 三个历史 zip；本机配置有 LFS filter 但没有 `git-lfs` 命令。
- 为什么重要：如果直接提交这些 zip，GitHub push 可能失败；如果长期需要保留历史大包，需要明确归档方案。
- 建议下一步：安装 Git LFS 后迁移大 zip，或只把最新可部署包和文档推到 GitHub，把超大历史包留在本地和桌面归档。

### P0-5 不要再把官网改回视频首屏

- 任务说明：把“宣传片独立资产，官网不放视频首屏”作为长期产品决策固化。
- 当前状态：v24 首页无 `<video>`、无 `assets/video`，品牌片不在首页。
- 为什么重要：用户已明确否定宣传片官网首屏方向。
- 建议下一步：如要使用宣传片，只做独立落地页或外发资产，不影响官网首页。

## P1 重要优化

### P1-1 首页内容层级与节奏优化

- 任务说明：在保留完整 46 个 section 的前提下，重新梳理信息层级，减少重复视觉段落，增强阅读节奏。
- 当前状态：v24 恢复完整内容，但由于历史版本多次叠加，部分区块可能存在重复、风格不完全统一、页面过长的问题。
- 为什么重要：用户要完整内容，但完整不等于堆砌；需要像咨询公司一样组织信息。
- 建议下一步：按“首屏 → 数据 → 核心项目 → 香港路径 → 案例 → 导师 → 信任中心 → 家长问题 → 表单”整理区块顺序，逐段优化。

### P1-2 核心产品页面补强

- 任务说明：强化 `associate-degree.html`、`postgraduate-application.html`、`gpa-management.html`、`application-guides.html` 等 SEO 页面。
- 当前状态：这些页面存在，但内容较短，适合作为后续专题页扩展基础。
- 为什么重要：专题页能承接搜索流量，也能让首页 CTA 指向更具体的转化页面。
- 建议下一步：为每个专题页补充适合人群、路径图、服务流程、案例、FAQ 和表单入口。

### P1-3 成功案例咨询公司化

- 任务说明：把案例从 offer 展示进一步升级为咨询案例：学生背景、挑战、规划动作、阶段结果、关键支持。
- 当前状态：首页 `case-library` 有 14 个案例卡，`success-cases.html` 有 offer 案例库。
- 为什么重要：案例逻辑越清楚，越能体现 Rain Education 的规划能力，而不只是晒结果。
- 建议下一步：挑 6 个代表性案例，做更完整的 case study 组件，并保持匿名化和合规边界。

### P1-4 导师团队可信度增强

- 任务说明：优化导师照片一致性、学校背景展示、擅长领域标签和服务链路说明。
- 当前状态：首页有 9 个 mentor card，`mentor-team.html` 有导师专题入口。
- 为什么重要：导师是高端教育咨询品牌可信度的重要支点。
- 建议下一步：统一照片比例，补充导师与顾问协同机制，避免单纯像“老师列表”。

### P1-5 表单与咨询转化优化

- 任务说明：优化快速表单、完整表单、电话、WhatsApp、微信二维码之间的转化路径。
- 当前状态：首页有 Netlify 表单、电话、WhatsApp、微信二维码、邮箱。
- 为什么重要：官网最终目标是预约评估与咨询转化。
- 建议下一步：检查 Netlify 表单后台是否收到字段；增加提交后感谢页路径和自动回复策略；减少手机端表单阻力。

### P1-6 SEO 基础优化

- 任务说明：完善 title、description、canonical、sitemap、结构化数据、专题页面关键词和内链。
- 当前状态：首页与专题页已有 meta description、canonical、sitemap 和 JSON-LD 基础。
- 为什么重要：香港副学士、香港本科、香港硕士、GPA 管理等关键词具备长期获客价值。
- 建议下一步：建立每个服务方向的关键词表，补充 FAQ schema 和专题页内容。

## P2 后续增强

### P2-1 多语言体系

- 任务说明：完善简体、繁体、英文切换，不再只依赖前端字典即时替换。
- 当前状态：`script.js` 已有语言切换、简繁转换和英文文本映射，但维护成本较高。
- 为什么重要：Rain Education 面向香港与国际家庭，多语言是品牌国际化基础。
- 建议下一步：长期可考虑拆分静态多语言页面或引入轻量内容配置。

### P2-2 博客 / 资讯中心

- 任务说明：建立香港升学、港八副学士、硕士申请、GPA 管理、家长问答等内容库。
- 当前状态：首页有 `content-hub` 与 SEO 页面入口，但还不是完整博客系统。
- 为什么重要：内容库能提升 SEO 和家长信任。
- 建议下一步：先用静态 HTML 专题页扩展，再考虑 CMS 或轻量生成流程。

### P2-3 成功案例专题库

- 任务说明：把成功案例做成可筛选、可分类、可长期维护的案例库。
- 当前状态：已有 `success-cases.html`，首页也有案例筛选。
- 为什么重要：案例是教育咨询官网最强信任资产之一。
- 建议下一步：按地区、项目层级、学生起点、服务动作做分类。

### P2-4 数据看板

- 任务说明：将升学率、案例数量、申请方向、offer 类型做成更可信的数据展示。
- 当前状态：首页已有固定数据卡片。
- 为什么重要：咨询公司风格需要可解释、可信的数据，而不是简单广告数字。
- 建议下一步：新增“数据如何统计”的说明或合规注释。

### P2-5 CRM 接入

- 任务说明：将表单提交接入 CRM、飞书、Notion、邮件自动化或客服系统。
- 当前状态：表单使用 Netlify Forms。
- 为什么重要：减少咨询线索丢失，提高跟进效率。
- 建议下一步：确认团队实际使用的 CRM，再做 webhook 或自动通知。

### P2-6 AI 客服

- 任务说明：为常见问题提供 AI 初筛，但不能替代顾问正式评估。
- 当前状态：未实现。
- 为什么重要：可提升响应效率，但必须有合规边界。
- 建议下一步：先整理 FAQ 和服务边界，再决定是否接入。

### P2-7 宣传片独立落地页

- 任务说明：为最终品牌宣传片制作独立页面或可分享链接。
- 当前状态：宣传片不在官网首页；v22 曾用于品牌片首屏，但已被 v24 否定。
- 为什么重要：宣传片仍是品牌资产，可用于家长、合作伙伴、学校和招生渠道。
- 建议下一步：如果用户需要，单独做 `/brand-film.html` 或私密分享页，不能影响首页定位。
